Source: /Users/brett/Documents/GitHub/Ancient-Art-of-War/WAR_Original_Files_3.5 (all files dated 22 Jun 1989). Analysed Nov 2026; brought up to date on 12 Nov 2026, after the remake was finished. The fuller account, including how the game plays (campaign play, the enemy commander, battles, sound, menus, the editors), is WAR_Analysis/README.md; the complete annotated disassembly is WAR_Analysis/WAR.EXE.asm (generated by WAR_Analysis/disassembler/gen_asm.py, needs capstone). ## WAR.EXE structure (from the disassembly)
Segments relative to load address: resident C code 0000:0000-28CF; startup + Phoenix overlay loader 028D (entry 028D:02FA); overlay table at 02F6:0000 (file 0x3160); 21 thunks at 0000:2FEE + 12n; data segment DGROUP at 08C6 (file 0x172E0, 0xB40 bytes, preloaded). Overlays 1 and 3-7 all load at 0000:30F0 (one at a time); overlay 2 loads at 0000:8520.

| Overlay | File offset | Size | Purpose |
|---|---|---|---|
| 1 | 0x032F0 | 21,552 | Main program: startup (CNF, PM), title/menu screens, scrolls, opponents, options shoppe, battle report, save/load game (S), data disk, the campaign editor's flows and scroll editor, hardware detection, disk copy-protection check, PE-PO picture loader, campaign loader (ovl1:7816-79B6) |
| 2 | 0x08720 | 1,504 | Manual copy protection (WarW) + welcome |
| 3 | 0x08D00 | 6,896 | Campaign editor: squads and flags (O1) |
| 4 | 0x0A7F0 | 2,768 | Campaign editor: map maker (O0) |
| 5 | 0x0B2C0 | 5,776 | Formation editor (O8 + PL) |
| 6 | 0x0C950 | 23,408 | Campaign play, strategic map (O5) |
| 7 | 0x124C0 | 20,000 | Battle screen (O6, O7, P0-PD) |

Key functions (all routines are now named in WAR.EXE.asm): load_file 0000:17ED; dos_open/read/write/delete/close 0000:260A/264E/2667/267E/268A; print_string 0000:2565; put_char 0000:24E7; load_picture_rle8 ovl1:8163; decode_picture_rle16 ovl5:470F (copy at ovl7:7E97); make_data_path ovl1:7816 (A:/B: prefix into DS:0B3E); key_disk_check ovl1:8341; copy_protection ovl2:8520. Map drawing: rt_0f2c draws all (squads rt_19D9 -> sprite routine rt_1B17, flags rt_1AE0, cursor rt_1836); rt_0eef erases.

Font: 8x8, 1 bit per pixel, 95 characters (space to '~') at DS:05C9 (8 bytes each). put_char expands each 4-bit nibble to CGA pixels through the table at DS:05B9 (default: set bits = colour 3, clear = colour 0, i.e. white on black); 40 characters per text row.

Findings: two copy-protection checks (INT 13h read of track 10 incl. bad sector 241 on the original floppy; manual word lookup via WarW). Joystick on port 201h. Hercules: `WAR HERC` (or no CGA found) sets the card to 720x348 graphics (herc_setup ovl1:8441, CRTC table DS:095E) and points the row table DS:096A at Hercules scanlines 72-271, so the CGA picture shows 640x200 in the middle, each 2-bit pixel as two mono pixels. Campaign names from a "T0".."TA" table at DS:08C1.

Sound: PC speaker (timer 2) and the Tandy/PCjr SN76496 (port C0h); the tunes are word tables in O2 and O7 (see the README's Sound section).

## WARET.DAT format (16-colour / VGA graphics) - DECODED
### Archive
- Bytes 0-3: dword offset of directory (0x39C47).
- Directory: 3 bytes (unknown), word entry count (49), then 49 x [word record ID, dword file offset].
- Each record: word payload length, byte checksum (sum of payload bytes & 0xFF), payload.

### Compression (same for every compressed record)
Run-length code, matches WARET.EXE main program at 0133:0382 (linear 0x16B2 in the EXEPACK-unpacked image):
- Read signed byte n. If n >= 0: copy the next n+1 bytes. If n < 0: repeat the next byte -n times (256-n).
- Stop as soon as the requested output size is reached (a run can be cut short; some records have a few unused bytes at the end).

### Text/data records
Payload = word uncompressed size, then the RLE stream. Used for T0-TA (records 40-50) and TITLES/DTITLES (15/16). Verified byte-identical to the loose files.

### Picture records
Loader at linear 0x1AE6 / 0x1B7C in WARET.EXE:
| Payload offset | Length | Contents |
|---|---|---|
| 0 | 48 | Palette: 16 x RGB, 8 bits per channel. **Each picture has its own palette.** |
| 48 | 2 | Uncompressed size (0x7D06 = 32,006 for full screens) |
| 50 | ... | RLE stream |

Unpacked data = word width (320), word height (200), word bytes per row (160), then pixels: 4 bits per pixel, 2 pixels per byte, high nibble = left pixel, rows top to bottom. (The encoder sometimes merges the last header byte into the first run.)

### Map sprites (in WAR.EXE, DS)
Squad poses at DS:031C (marching), 0338 (standing, no orders: start of game), 0354 (fighting), 0370 (weak, condition <= 10), 038C (small figure: a squad of spies only, [A090] = 2); flag at DS:03A8. The letters A, B and K for the Formation preview are at DS:03C4, 03D0, 03DC (8x6). 28 bytes each: word width (1), word height in line pairs (6), then per line pair a big-endian 2bpp word for the even line and one for the odd line; only colours 0 and 3. Drawn by rt:1B17: friendly squads / white flags = white figure + black outline (pixels left and right of figure pixels, within the 8-pixel word); enemy squads / black flags = black figure + white outline. Pose chosen in rt:19D9 from the squad's state (moving speed 9EB0, fighting A0F4, figure A090) and condition. Enemy squads are hidden unless seen, unless rule "Enemy is seen" = 80 (always).

## Campaign data
| File | Contents |
|---|---|
| T0-TA | The 11 built-in campaigns, 1,460 bytes each: 840-byte story text (0x000 -> DS:9782), 200-byte map (0x348 -> DS:9D82), 400-byte army (0x410 -> DS:9E60), 2-byte opponent (0x5A0 -> DS:A67C), 18-byte rules (0x5A2 -> DS:A705). Loaded by ovl1:78AD. In the text, a 0x01 follows each capital letter: a capital is drawn 16 wide and takes two cells on the scroll. |
| TITLES | 876 bytes: 12 three-byte file names (T0..TB), then 840 bytes of scroll text (26 rows of 32) with 0x01 after capitals: the "TITLES" heading, the 11 campaigns on every other row, then "( data disk )". |
| DTITLES | Same layout for a new data disk; first entry "( war disk )". New campaigns take the names in the order listed (T1, T3, T4 ... TA, T2, TB); removing one moves its name to the end. |
| F | 420 bytes: the formations. Three tables of 10 formations x 14 men: type (0 knight, 1 barbarian, 2 archer), x (byte column 44-75; archers stand 2 further back) and y (line pair). Formation 0 lines the men along a fort wall, 1-5 are fixed, 6-9 can be changed in the formation editor (which writes F to the WAR disk, each formation sorted by x). The enemy's squad is mirrored (x = 76 - x). |
| WARW | 672 bytes: the word list for the manual question ("On page N, what is word N in paragraph N"), loaded as "WarW" by overlay 2. Decoded: XOR each byte with a key that starts at 117 and goes up by 23 (low 8 bits) per byte, up to the first three zero bytes; then entries separated by ';', each a page byte, a byte (word << 4 \| paragraph) and the word. |
| S | Saved game (on the data disk): 217Eh bytes of the data segment, DS:8868-A9E5 (the view, the enemy's cell tables, the supply map, the path and route memories, the map, the armies and every squad table, the opponent's values, the counters and the rules). Laid out in the README's Saved games section. |

### Campaign map (confirmed Nov 2026)
- 10 tiles across x 20 down (320x400 px), row by row from the top, 200 bytes at T-file offset 0x348.
- Each byte = tile number 1-72; tile number N = tile index N-1 in M (CGA) or WARET.DAT record 30 (VGA). Both tile sets share the same order, so one map serves both modes.
- The game shows a little over 9 tile rows (182 lines) with two text rows below (a message row and the command line), scrolling vertically. Verified: T0 rows 11-19 match the screenshot on manual page 9 (scan 11) exactly.
- In memory the map is drawn into a 320x400 2bpp buffer at DS:0B68 stored as two fields: even lines at +0, odd lines at +3E80h (80 bytes per line).

## Opponents and rules (in the T file)
- Opponent (word at 0x5A0): 0 Athena, 1 Alexander the Great, 2 Geronimo, 3 Crazy Ivan, 4 Caesar, 5 Genghis Khan, 6 Napoleon, 7 Sun Tzu.
- Rules (9 words at 0x5A2): villages supply food (0/1), forts supply food (0/1), supply-line range (1, 2, 4), forts train men (30, 60, 120), your men's shape (1 prime, 2 good, 4 out of), enemy is seen (20 close, 40 far, 80 always), water (10, 20, 40), mountains (4, 8, 16), forest (3, 6).

## Open questions
- How WARET.EXE colours the shared 2bpp sprites (O3, O6, O8) in 16-colour mode (sprite blitter near linear 0x1684, plane writes via port 0x3C5 at 0x1640). The remake draws them with the CGA colours mapped to the nearest colours of each 16-colour picture, and the map sprites in white and black.
- WARET.EXE's own logic was not disassembled; the remake assumes it plays like WAR.EXE.
