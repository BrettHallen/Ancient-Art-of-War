# The Ancient Art of War at Sea: 3.5" disk file reference (WAS_Original_Files_3.5)

Source: `WAS_Original_Files_3.5` in the repo (all files dated 11 Jul 1988). First analysed 12 Nov 2026, the same way as the land game (see `WAR_Analysis/WAR_file_reference.md`; At Sea is by the same authors and built the same way). The disassembly is `WAS_Analysis/WAS.EXE.asm` (generated by `WAS_Analysis/disassembler/gen_asm.py`, needs capstone); the findings so far are in `WAS_Analysis/README.md`. All graphics are extracted by `WAS_Graphics/extract_graphics.py` into `WAS_Graphics/CGA` and `WAS_Graphics/VGA`.

**File names:** as the handoff guessed, most WAS files are WAR's names with an S in front (O0-O8 -> SO0-SO8, P* -> SP*, M -> SM, CNF -> SCNF, TITLES -> SITLES). But the **campaigns are S0-SA** (WAR's T0-TA), and the **saved game is SS** (WAR's S).

## Two executables, two graphics sets
| File | Size | What it is |
|---|---|---|

Main program compressed with Microsoft EXEPACK ("Packed file" at 0xACF7); 4 MS-LINK overlay modules (MZ headers, overlay numbers 1-4) at file offsets 0xB000, 0x11400, 0x14A00, 0x1C600. | WAST.DAT | 194,438 | Resource archive for WAST.EXE: the 16-colour pictures and map tiles plus copies of the data files. **Fully decoded** (below). |

Note for the remake: the At Sea 16-colour set is the **Tandy 1000** version. Its colours are the standard 16 (the same as EGA/VGA's default palette), so it looks the same on a VGA.

## WAS.EXE structure (from the disassembly)
- MZ header 0x400 bytes, 151 relocations, entry 06C5:02FA (WAR.EXE: 028D:02FA).
- Resident C code and library `rt` 0000:0000-6C4F (WAR: 0000-28CF, so much more of the game is resident).
- Root (startup + loader) at segment 06C5; overlay table at image 72E0h (file 0x76E0); 61 thunks at 0000:736E + 12n (WAR had 21).
- Two overlay areas: overlays 1-5 load at 0000:7650; overlays 6 and 7 (flag 5) load at 0000:C9B0, beside overlay 5.
- Data segment DGROUP at segment 0FF9 (file 0x23AB0, 3F10h bytes, preloaded); stack at 16D8:0100.

Routines named so far: 105 matched to WAR.EXE.asm by their instruction sequence (the C library, file I/O, text, sound, delay, random, the scroll and menu helpers, the editors' helpers, some campaign-play routines) and 16 named from WAS.EXE itself (see the NAMED FUNCTIONS list at the top of WAS.EXE.asm).

Font: the same 8x8 font as WAR.EXE (95 characters, byte-identical), at DS:089C.

Copy protection: the key-disk check only (key_disk_check ovl1:CF96, same code as WAR.EXE: INT 13h read of a track of the original floppy). **No manual word question** (no WarW-type file). "DPQZSJHIU 2:94 EBWF NVSSZ" (= "COPYRIGHT 1983 DAVE MURRY", shifted +1) is at DS:0835, as in WAR.

## Pictures (CGA) - decoded
New format for all of them (not WAR's two formats):

- Two fields: even lines, then odd lines. Each field = word N, then N codes:
  - code c <= 200: repeat the next byte c times;
  - c > 200: copy the next c - 200 bytes.
- Each field unpacks to exactly 8000 bytes (80 bytes x 100 lines, 2 bits per pixel). load_picture (ovl1:CBEA) writes even lines at the destination and odd lines at +3E80h.
- WAS.EXE leaves the CGA palette at the BIOS default for mode 4 (palette 1: black, cyan, magenta, white). set_cga_palette is reached only through rt_30AE: palette 0 for flashes in the sea battle (overlay 5) and in ovl1_bc67 when option [684D] is set.

| SPE, SPF | Parchment scrolls | 3, 4 |

## WAST.DAT format (16-colour graphics) - decoded
**The same archive and run-length code as WARET.DAT** (`WAR_file_reference.md`):
- Bytes 0-3: dword offset of the directory (0x2F6A9). Directory: 3 bytes, word count (36), then 36 x [word record ID, dword offset]. Each record: word payload length, byte checksum, payload.
- Run-length code: signed byte n; n >= 0 copy n+1 bytes, n < 0 repeat the next byte -n times; stop at the requested size.
- **Difference from WARET.DAT: pictures and tiles carry no palette.** Payload = word unpacked size, then the run-length stream. All of them use the standard 16 colours (black, blue, green, cyan, red, magenta, brown, light grey, dark grey, light blue, light green, light cyan, light red, light magenta, yellow, white); the extracted pictures match the CGA ones with these colours.
- Pictures unpack to word width 320, word height 200, word bytes per row 160, then 4 bits per pixel (high nibble = left pixel).

| Record | Contents |
|---|---|
| 1-10, 13, 29 | Pictures (see the table above) |
| 15, 16 | SITLES, SDITLES (compressed) |
| 20-28 | SO0-SO8, uncompressed. SO0-SO5 and SO8 are byte-identical to the loose files; **SO6 (17 bytes) and SO7 (80 bytes) differ** (16-colour versions of some data) |
| 30 | 90 map tiles (tiles 1-90), 16 colours: unpacked 90 x [word width in words 8, word height/2 10, 320 bytes], 32x20 each |
| 31 | 4 more map tiles (91-94), same layout |
| 40-50 | S0-SA (compressed). Each is the first 2180 bytes of the loose file (the 40 extra bytes of the 2220-byte files are left out) |

## Campaign files S0-SA - layout from load_campaign (ovl1:C388)
| Offset | Size | Loaded to | Contents |
|---|---|---|---|
| 0x000 | 840 | DS:4E53 | Story text, 26 rows of 32, with 0x01 after each capital (as WAR) |
| 0x348 | 200 | DS:5BFF | Map: 10 tiles across x 20 down, row by row; byte N = tile N (index N-1 in SM / the 16-colour tiles). Checked by drawing S0, S5 and S9 |
| 0x410 | 480 | DS:5CDD | Ships: 40 ships, stored field by field (below) |
| 0x5F0 | 2 | DS:646F | Opponent (word) |
| 0x5F2 | 18 | DS:64AD | Rules: 9 words |
| 0x604 | 600 | DS:609F | Ship names: 40 x 15 bytes, NUL-terminated |
| 0x85C | 40 | DS:6025 | Only in the 2220-byte files (S1, S3, S4, S5, S7, S8); all zero in every file. The 2180-byte files end before it |

Ship block (40 ships):
| Offset | Size | Field |
|---|---|---|
| 0 | 40 words | Side: -1 or 0 (as WAR: -1 friend, 0 foe; to confirm) |
| 80 | 40 words | 9999 = empty slot, else 0 |
| 160 | 40 words | X: byte column in the map buffer (x4 = pixels) |
| 240 | 40 words | Y: line pair (x2 = pixels) |
| 320 | 40 bytes | Not yet identified (20 for most ships, 0 in empty slots; perhaps a condition) |
| 360 | 40 bytes | Looks like the squadron number (ships share it in threes in S1; 255 = none) |
| 400 | 40 bytes | Not yet identified (0-5) |
| 440 | 40 bytes | Not yet identified (0-3) |
The ships' map addresses are (y+1)*80 + x (ship_map_addresses ovl1:C4D8). The quick reference card: a squadron has 1-3 ships, all squadrons of one colour form the fleet; ship types are flagship, ship-of-the-line, frigate and merchantship.

Rules (9 words): the rule lines in SO3 are "Ports repair ships", "Ports need supplies", "Wind changes", "Rough water is", "Shallow water is", "Visibility is", the crew ("green / average / crack") and cannon aim ("manual / automatic"), with values steadily/slowly/never, often/rarely/never, very risky/risky/mild, safe, short/medium/long/unlimited. Which word is which: to do. S0's are 20, 10, 0, 0, 1, 80, 0, 2, 0.

Opponents (SO2): Thor Foote, the Duke of Medina Sidonia, Blackbeard, Martin Tromp, John Paul Jones, Lord Admiral Nelson (6, in SPJ's order).

| File | Contents |
|---|---|
| S0-SA | The 11 built-in campaigns (2,180 or 2,220 bytes): The Bane of Oldain, The Race for the Crown, Running the Gauntlet, The Last Crown, Attack of the Superpower, 1588 The Spanish Armada, 1676 Sicily / 1798 The Nile, 1759 Quiberon Bay, 1805 Trafalgar, 1941 Bismarck, You Only Live Thrice |

## Data in WAS.EXE's data segment
Strings for the map and battle screens ("Wind is from the ...", "You sank the ...", "grapples", "Zoom Pass", "ENEMY FRIGATE", "MERCHANT SUPPLIES SQUAD", "CROWN CAPTURED"), the file names (SM at DS:002A, S0-SB at DS:0BB5), the font (DS:089C) and, from about DS:1100 on, what look like the map sprites (ships, flags) and tables. To be mapped as the code is named.
