# The Ancient Art of War at Sea: 3.5" disk file reference (WAS_Original_Files_3.5)

Source: `WAS_Original_Files_3.5` in the repo (all files dated 11 Jul 1988). First analysed 12 Nov 2026, the same way as the land game (see `WAR_Analysis/WAR_file_reference.md`; At Sea is by the same authors and built the same way). The disassembly is `WAS_Analysis/WAS.ASM` (generated by `WAS_Analysis/disassembler/gen_asm.py`, needs capstone); the findings so far are in `WAS_Analysis/README.md`. All graphics are extracted by `WAS_Graphics/extract_graphics.py` into `WAS_Graphics/CGA` and `WAS_Graphics/VGA`.

**File names:** as the handoff guessed, most WAS files are WAR's names with an S in front (O0-O8 -> SO0-SO8, P* -> SP*, M -> SM, CNF -> SCNF, TITLES -> SITLES). But the **campaigns are S0-SA** (WAR's T0-TA), and the **saved game is SS** (WAR's S).

## WAS.EXE structure (from the disassembly)
- MZ header 0x400 bytes, 151 relocations, entry 06C5:02FA (WAR.EXE: 028D:02FA).
- Resident C code and library `rt` 0000:0000-6C4F (WAR: 0000-28CF, so much more of the game is resident).
- Root (startup + loader) at segment 06C5; overlay table at image 72E0h (file 0x76E0); 61 thunks at 0000:736E + 12n (WAR had 21).
- Two overlay areas: overlays 1-5 load at 0000:7650; overlays 6 and 7 (flag 5) load at 0000:C9B0, beside overlay 5.
- Data segment DGROUP at segment 0FF9 (file 0x23AB0, 3F10h bytes, preloaded); stack at 16D8:0100.

Routines named so far: 105 matched to WAR.EXE.asm by their instruction sequence (the C library, file I/O, text, sound, delay, random, the scroll and menu helpers, the editors' helpers, some campaign-play routines) and 256 named from WAS.EXE itself, 67 of them in the sea battle and boarding, the enemy commander's in ovl4:B03E-EF2E and 33 in the menus (step 6) (see the NAMED FUNCTIONS list at the top of WAS.ASM).

Video: CGA mode 4, or Hercules with `WAS HERC` (an argument starting with H; see `README.md`): the same drawing, with the row table DS:0D3B pointing at Hercules scanlines 72-271 (from byte 4, 90 bytes a row, four banks), so the CGA bytes show as 1-bit pixels, 640x200 in the middle of 720x348. [0ECB]: 0 CGA, 1 Hercules, 2 when the BIOS equipment word's video bits are 00 (an EGA or VGA card).

Font: the same 8x8 font as WAR.EXE (95 characters, byte-identical), at DS:089C.

Copy protection: the key-disk check only: key_disk (ovl1:A9A9) calls key_disk_check (ovl1:CF96, same code as WAR.EXE: INT 13h reads of the original floppy) and looks for the copyright string DS:0BD9 in what it read; without it startup gives up (ovl1:76B3). `WAS_Analysis/tools/dosbox/setup_was.sh` patches a copy of WAS.EXE there (file offset 7AB3h, `75 07` -> `EB 07`) so it runs in DOSBox. **No manual word question** (no WarW-type file). "DPQZSJHIU 2:94 EBWF NVSSZ" (= "COPYRIGHT 1983 DAVE MURRY", shifted +1) is at DS:0835, as in WAR.

## Pictures (CGA) - decoded
New format for all of them (not WAR's two formats):

- Two fields: even lines, then odd lines. Each field = word N, then N codes:
  - code c <= 200: repeat the next byte c times;
  - c > 200: copy the next c - 200 bytes.
- Each field unpacks to exactly 8000 bytes (80 bytes x 100 lines, 2 bits per pixel). load_picture (ovl1:CBEA) writes even lines at the destination and odd lines at +3E80h.
- The pictures show in CGA palette 1 (black, cyan, magenta, white), **except the scrolls SPE and SPF, in palette 0** (black, green, red, yellow), as in WAR: show_scroll (ovl1:7F1A) calls scroll_palette (ovl1:BC67), which switches to palette 0 when option [684D] is set (it is, in the shipped SCNF). Checked in DOSBox. The sea battle (overlay 5) also flashes between the palettes.

## WAST.DAT format (16-colour graphics) - decoded
**The same archive and run-length code as WARET.DAT** (`WAR_file_reference.md`):
- Bytes 0-3: dword offset of the directory (0x2F6A9). Directory: 3 bytes, word count (36), then 36 x [word record ID, dword offset]. Each record: word payload length, byte checksum, payload.
- Run-length code: signed byte n; n >= 0 copy n+1 bytes, n < 0 repeat the next byte -n times; stop at the requested size.
- **Difference from WARET.DAT: pictures and tiles carry no palette.** Payload = word unpacked size, then the run-length stream. All of them use the standard 16 colours (black, blue, green, cyan, red, magenta, brown, light grey, dark grey, light blue, light green, light cyan, light red, light magenta, yellow, white); the extracted pictures match the CGA ones with these colours.
- Pictures unpack to word width 320, word height 200, word bytes per row 160, then 4 bits per pixel (high nibble = left pixel).

| Record | Contents |
|---|---|
| 1-10, 13, 29 | Pictures (see the table above) |
| 15, 16 | SITLES, SDITLES (compressed) |
| 20-28 | SO0-SO8, uncompressed. SO0-SO5 and SO8 are byte-identical to the loose files; **SO6 (17 bytes) and SO7 (80 bytes) differ** (16-colour versions of some data) |
| 30 | 90 map tiles (tiles 1-90), 16 colours: unpacked 90 x [word width in words 8, word height/2 10, 320 bytes], 32x20 each |
| 31 | 4 more map tiles (91-94), same layout |
| 40-50 | S0-SA (compressed). Each is the first 2180 bytes of the loose file (the 40 extra bytes of the 2220-byte files are left out) |

The quick reference card: a squadron has 1-3 ships, all squadrons of one colour form the fleet; ship types are flagship, ship-of-the-line, frigate and merchantship.

Rules (9 words, DS:64AD-64BD): the rule lines in SO3 are "Ports repair ships", "Ports need supplies", "Wind changes", "Rough water is", "Shallow water is", "Visibility is", the crew ("green / average / crack") and cannon aim ("manual / automatic"), with values steadily/slowly/never, often/rarely/never, very risky/risky/mild, safe, short/medium/long/unlimited. From campaign play (ovl4): word 0 [64AD] the chance (of 128) of a repair each time an anchored squadron is fed; 1 [64AF] what a repair port holds (supply ports and crowns twice that; 20 or more: they never run out); 2 [64B1] not used in campaign play; 3 [64B3] rough water (0 very risky, 1 safe, else risky); 4 [64B5] how fast your squadrons eat (chance (x 32 - 10)/128 of 2 supplies each time); 5 [64B7] visibility (2|dx| + |dy| under it; 80 = always seen); 6 [64B9] shallow water (as 64B3); 7 [64BB] wind changes (1 rarely 16/128, 2 often 64/128, every 31 ticks); 8 [64BD] not used in campaign play. S0's are 20, 10, 0, 0, 1, 80, 0, 2, 0.

Opponents (SO2): Thor Foote, the Duke of Medina Sidonia, Blackbeard, Martin Tromp, John Paul Jones, Lord Admiral Nelson (6, in SPJ's order). Each has 25 words at SO2 + 277h + 50 x n (pointers DS:6872-687C, ovl1:8CC6), copied to DS:604D-607D when chosen (ovl1:90F7; the demo takes opponent 2, ovl1:88A7). Known so far: [6053] the chance (of 128) that the enemy's squadron is hit in a fight on the map (yours: 65), [6057] the chance of forgetting a threatened crown after a win, and (/ 8) of a squadron by a port simply staying (115: never for supplies or repairs), [6059] how fast the enemy eats (of 128), [605B] the ratio of your squadrons to theirs that makes them offer to surrender, [606D] (x 8 of 128) how often a lost merchant tells them where your crown is; [6065], [6067], [6071], [6073] are changed by end_check. The enemy commander's (step 5, `WAS_Analysis/README.md`): [604D] squadrons that make a crown target crowded, [6055] a flagship squadron's caution, [605D] hunger, [605F] the damage it puts up with, [6061] randomness in choosing targets, [6063] how far it goes to attack (x 8 steps), [6065] the strength margin it attacks with, [6071] how much your strength puts it off, [6073] its crown's guard, [6075] the chance of going for your crown or flagship; boarding: [6077] officers, [6079] their pistols, [607B] the men's blows.

## Data in WAS.EXE's data segment
- Strings for the map and battle screens ("Wind is from the ...", "You sank the ...", "grapples", "Zoom Pass", "ENEMY FRIGATE", "MERCHANT SUPPLIES SQUAD", "CROWN CAPTURED"), the file names (SM at DS:002A, S0-SB at DS:0BB5), the font (DS:089C).
